# 实时供货与成本核验

## 强制顺序

收到当前商品的销量链接后、记录链接和打开平台页面前，先执行供货核验。采集完成后，如任一保留 SKU 的采集原价低于配置阈值，再使用同一份当前品类文档取得成本。每次都使用配置中的实时文档，不使用上一次结果、截图、本地商品目录或记忆代替。

先运行 `audit`。只有 `collection_ready=true` 才继续；若为 `false`，停止并向用户索取当前品类供货文档。不得自行复用旧品类 URL。用户提供后，把 URL 写入 `availability.document_url`，并把当前 `catalog_roots` 同顺序写入 `availability.bound_catalog_roots`，再次运行 `audit`。

1. 使用 `browser:control-in-app-browser` 打开 `availability.document_url`。
2. 关闭不影响查看的登录提示；需要登录、验证码或权限时交给用户。
3. 按 `Ctrl+F` 打开文档查找，输入历史条目的 `product_code`；仅在供应商明确提供时使用预留时记录的别名。
4. 把范围切换为“所有工作表”，执行“查找全部”，只采信精确结果。
5. 检查全部精确结果的工作表、单元格和值，不只看当前可见区域。
6. 只要任一结果出现在配置的 `sold_out_sheets`，立即判定不可采集；售罄结果优先于旧在售表结果。
7. 没有售罄命中时，至少需要一个正常供货工作表的精确命中。记录真实工作表名、A1 单元格和命中文字。
8. 如果文档显示库存数量，至少一个可供 SKU 必须明确大于零；全部为零、空白或无法读清时停止。

查无结果、只有模糊结果、相邻货号、只命中售罄表、文档打不开、无法确认所有工作表范围或匹配关系不明确时，一律停止。不要记录链接或打开平台页。已预留商品仍永久保留在历史中，避免以后重复选择。

## 记录证据

核验通过后立即运行；以下内容必须替换为真实结果：

```bash
python "<SKILL_DIR>/scripts/listing_workflow.py" --root "<WORKSPACE>" confirm-availability \
  "<OUTPUT_DIR>" --query "SUPPLIER-CODE" --matched-text "SUPPLIER-CODE" \
  --active-sheet "ACTIVE-SHEET" --active-cell '$A$2' \
  --scope all_sheets --sold-out-status clear
```

PowerShell 和 Bash 都使用单引号包住含 `$` 的单元格地址。命令只记录浏览器核验结果；没有完成上述浏览器步骤时不得调用。

`confirm-availability` 只记录供货状态，不记录供应商成本。供货证据绑定当前商品、配置中的文档和售罄表、当前链接及核验时间。下列情况要求重新打开文档核验并再次运行命令：

- 超过 `fresh_minutes`。
- 替换已记录的链接。
- 修改供货文档、售罄工作表或有效时间。
- 妙手编辑耗时导致完成标记前证据过期。

## 采集后的成本取证

先在妙手记录全部保留 SKU 尚未修改的采集原价。只有原价严格低于 `collection.price_threshold` 的 SKU 才强制读取成本；原价等于或高于阈值的 SKU 保持原价，不需要成本字段。

对每个低价 SKU 执行以下检查：

1. 重新打开当前配置绑定的 `availability.document_url`，用已确认的货号或明确别名精确查找，不复用旧截图或记忆。
2. 在精确命中行中确认价格字段确实代表供应商成本，并记录三格共同工作表名，以及该行货号、供应商 SKU 和成本各自的 A1 单元格与原始文字；人工确认三格属于记录的工作表，脚本再校验三格行号相同。
3. 确认成本币种与妙手采集原价币种一致，销售单位、件数和套装口径一致，并把供应商币种与单位写入价格 JSON。不得自行猜测汇率、含税关系、运费或套装拆分方法。
4. 确认妙手 SKU 与供货文档的颜色、尺码、型号、数量或其他变体逐一对应，并把供货表中的完整变体文字写入 `supplier_sku_text`。文档明确给出统一产品成本时，可把同一成本证据用于所有一致 SKU；文档按变体定价时必须逐 SKU 使用对应成本。
5. 只采信清晰的数值成本。相邻商品价格、价格区间下限、“起”价、已删除价格、无法识别含义的数字或模糊匹配均不能作为成本。

任一低价 SKU 的成本、币种、计价单位或 SKU 对应关系无法确认时，停止整个商品的编辑。不得猜值、不得只完成部分 SKU，也不得删除本次其他采集记录或运行 `mark-collected`。

成本本身由 `record-pricing` 随逐 SKU 价格记录保存，不传给 `confirm-availability`。价格证据绑定当时的供货证据、已记录链接以及 `price_threshold`、`minimum_profit_rate` 等相关配置；其中任一项变化或供货证据过期，价格证据即失效，必须重新核验、计算并记录。
