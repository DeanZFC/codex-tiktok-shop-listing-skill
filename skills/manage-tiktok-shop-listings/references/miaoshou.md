# 妙手采集与商品编辑

## 打开与采集

用户链接的顺序就是销量排序，始终保持 `1=最高销量`。先完成供货核验和 `record-links`，再用 `open_product_urls.py` 在 Microsoft Edge 打开全部链接。等待短链重定向，确认页面确实是当前同款。

保持每个平台一个商品页，让用户手动点击妙手扩展并选择存入公用采集箱。Codex 不操作或声称操作浏览器扩展弹窗。用户回复“采集完成”前停止。

## 选择最终记录

接管已登录的妙手公用采集箱后：

1. 按平台、货源 ID、标题和采集时间定位本次记录。
2. 对照供应商原图和资料，判断颜色、外形、型号、数量、包装和配件是否同款。
3. 排除仍在处理、采集失败、售罄无数据或不合款记录。
4. 从剩余记录中选择销量顺序最靠前的一条作为最终商品。
5. 所有记录都不可用时停止，不编辑其他商品，不完成历史状态。

## 编辑规则

- 标题与内容使用当前输出目录的店铺文案，只保留有来源的事实。
- 最终图片数量必须准确等于 `collection.final_image_count`。第 1 张保留最终记录中与供应商一致的主图；后续按销量顺序加入其他合款平台主图，不足时从任一合款记录补充正面、同色、同型号图片。
- 供应商资料是颜色、型号、款式、规格、包装数量和配件组成的唯一事实来源。供应商只有一个变体时删除平台多余变体；供应商明确有多个变体时只保留逐一对应项及其 SKU 图片。
- 只填写平台必填项和配置中的优先事实字段。无法确认的属性留空或删除。
- 规格或尺寸只使用供应商数据，不猜单位或数值。
- 对每个 SKU：价格严格低于 `collection.price_threshold` 时改为 `collection.price_replacement`；等于或高于阈值保持原价。所有 SKU 库存改为 `collection.sku_inventory`。
- 保存后刷新或重新打开，逐项复核标题、内容、图片顺序、变体、属性、规格、价格和库存确实落盘。

## 清理与完成

最终商品保存复核后，删除本次其余全部采集记录，包括不合款、失败、较低销量和未采用的合款记录。删除前按采集箱 ID、平台和货源 ID 三重核对；绝不删除最终采用记录。刷新采集箱，确认本次只剩最终商品。

遇到发布、付费、验证码、权限变更、覆盖其他商品或无法唯一识别删除目标时停止并交给用户。

只有以下条件全部满足才能运行 `mark-collected`：

- 至少一条合款记录可用。
- 最终商品已保存并刷新复核。
- 图片数量准确。
- 变体、规格、价格和库存符合配置与供应商事实。
- 本次其余记录已删除。
- 供货证据仍在有效期内；过期时已重新核验。
